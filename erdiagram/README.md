# ER Diagram Generator

A command-line tool that turns an Entity-Relationship model into a PNG diagram (Chen notation) using Graphviz. The model can come from a hand-written JSON file or be generated by Google Gemini from a plain-English description of a system.

## Features

- Renders ER diagrams in Chen notation:
  - Entities as boxes, weak entities with a double border
  - Relationships as diamonds, identifying relationships with a double diamond
  - Attributes as ellipses, with:
    - **Primary key**: underlined
    - **Partial key**: dashed underline
    - **Multivalued**: double border
    - **Derived**: dashed border
    - **Composite**: nested child attributes, any depth
  - Relationship attributes, n-ary relationships, and recursive relationships
  - Cardinality labels on edges; total participation drawn as a thicker edge
- Natural-language input: describe a system in a text file and Gemini produces the JSON model.

## Project Structure

| File | Purpose |
|---|---|
| `main.py` | CLI entry point and Graphviz rendering (`renderERDiagram`) |
| `classes.py` | Dataclasses (`ERDiagram`, `Entity`, `Attribute`, `Relationship`, `Participant`) with `fromDict` parsers |
| `model.py` | Gemini client and the system prompt that converts a description into ER JSON |
| `er_json_schema.md` | Full specification of the JSON format and validation rules |

## Requirements

- Python 3.10+
- The [Graphviz](https://graphviz.org/download/) binaries installed and on your `PATH` (the Python package alone is not enough)
- Python packages:

```bash
pip install graphviz google-genai python-dotenv
```

## Configuration

Only needed for text-description input. Create a `../.env` file next to `main.py`:

```env
GEMINI_API_KEY=your_api_key_here
GEMINI_MODEL=your_gemini_model_name
```

Note that `model.py` reads these at import time, so both variables must be set even if you only use JSON input.

## Usage

```bash
python main.py
```

You will be prompted for:

1. **Input format**: `1` for a JSON file, `2` for a text description file
2. **Input file name**
3. **Output file name** (without extension; defaults to `er_diagram`)

The diagram is written to `<output_name>.png`.

### Option 1: JSON input

Provide a file following the schema in [`er_json_schema.md`](er_json_schema.md). Minimal example:

```json
{
  "entities": [
    {
      "name": "Employee",
      "attributes": [
        { "name": "SSN", "isPrimaryKey": true },
        { "name": "Phone", "isMultiValued": true },
        { "name": "Age", "isDerived": true }
      ]
    },
    {
      "name": "Department",
      "attributes": [
        { "name": "DeptID", "isPrimaryKey": true },
        { "name": "Name" }
      ]
    }
  ],
  "relationships": [
    {
      "name": "Works_In",
      "participants": [
        { "entity": "Employee", "cardinality": "N", "isTotalParticipation": true },
        { "entity": "Department", "cardinality": "1" }
      ]
    }
  ]
}
```

### Option 2: Text description input

Write a plain-text file, for example:

```text
A company has employees identified by SSN. Each employee has a name, several
phone numbers, and a date of birth. Every employee must work in a department,
but a department may have no employees. Departments have an ID and a name.
```

The description is sent to Gemini with a system prompt that enforces the schema and modeling rules (key requirements, weak entities, cardinalities, derived and multivalued attributes, and so on). The returned JSON is parsed and rendered.

## How It Works

1. `main.py` loads JSON (or calls `generateJson` in `model.py` for a description).
2. `ERDiagram.fromDict` parses the dict into dataclasses.
3. `renderERDiagram` builds a `graphviz.Graph`: entities first (so their IDs are known), then relationships, with attributes added recursively.
4. `graph.render(out, cleanup=True)` produces the PNG and removes the intermediate `.gv` file.

The layout engine defaults to `dot`; `renderERDiagram` accepts an `engine` argument (e.g. `neato`, `fdp`) if you want a different layout.

## Error Handling

The CLI reports a missing input file, invalid JSON, and any other exception (such as a relationship that references an undefined entity) with a message instead of a traceback.
